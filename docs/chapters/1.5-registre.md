# 1.5 — Registre d'images et publication

Le tag `1.5` ajoute un workflow GitHub Actions qui publie les tags pédagogiques dans GitHub Container Registry (GHCR). L'image est alors réutilisable depuis une autre machine ou un cluster.

## Publication manuelle

```sh
export IMAGE=ghcr.io/rchrdkvcs/demo-fyc-api:1.5
docker build -t "$IMAGE" .
docker login ghcr.io
docker push "$IMAGE"
```

Sur une autre machine :

```sh
docker pull ghcr.io/rchrdkvcs/demo-fyc-api:1.5
```

Ne poussez jamais de secret dans une image. La valeur `APP_KEY` et les identifiants PostgreSQL sont injectés au démarrage.

## Publication automatique

Le workflow `.github/workflows/publish-image.yml` se déclenche pour un tag qui respecte `module.chapitre`, par exemple `1.5` ou `2.2`. Il utilise le `GITHUB_TOKEN` pour GHCR ; l'image peut nécessiter un réglage de visibilité dans les paramètres Packages du compte.

Un cluster qui ne peut pas accéder à GHCR peut utiliser une image locale : construisez `demo-fyc-api:2.2`, puis chargez-la dans Kind ou K3d selon la procédure du checkpoint Kubernetes.
