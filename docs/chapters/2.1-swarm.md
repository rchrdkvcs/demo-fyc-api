# 2.1 — Réplication et Docker Swarm

Le tag `2.1` est le premier état du module 2. Il reprend l'image publiée au checkpoint `1.5` et montre la différence entre plusieurs réplicas déclarés et un processus unique sur un VPS.

## Lancer l'atelier

Sur un hôte Docker avec Swarm activé :

```sh
docker swarm init
cp .env.example .env
node ace generate:key
set -a; . ./.env; set +a
export API_IMAGE=ghcr.io/rchrdkvcs/demo-fyc-api:1.5
docker stack deploy -c deploy/swarm/stack.yaml demo-fyc
docker stack services demo-fyc
docker service ps demo-fyc_api
```

La clé est écrite dans le fichier `.env` local puis exportée pour la commande
Swarm. Ne la committez pas et ne la placez pas dans le fichier YAML.

## Ce qu'il faut observer

- `replicas: 3` exprime un état désiré ; Swarm recrée un conteneur arrêté ;
- `update_config` décrit un remplacement progressif ;
- le routage ingress distribue les requêtes du service API ;
- le volume PostgreSQL de cet exemple reste attaché au nœud qui le fournit : la réplication de l'API ne rend pas la base hautement disponible.

```sh
docker service scale demo-fyc_api=1
docker service scale demo-fyc_api=3
docker service rm demo-fyc_api
docker stack rm demo-fyc
```

Swarm est une étape de comparaison. Le chapitre `2.2` introduit Kubernetes, ses objets et son modèle de réconciliation plus riche.
