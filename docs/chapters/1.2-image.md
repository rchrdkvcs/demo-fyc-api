# 1.2 — Construire l'image

## Ce que ce checkpoint ajoute

- `Dockerfile` multi-stage : `dependencies` (pnpm install) → `build` (`pnpm build`) → `runtime` (Node 24 slim, dépendances de production uniquement) ;
- exécution avec l'utilisateur non privilégié `node`, port `3333`, `HEALTHCHECK` sur `/health` ;
- `.dockerignore` : ni `.env`, ni `node_modules`, ni `.git` dans le contexte de build.

## Lancer

```sh
docker build -t demo-fyc-api:1.2 .
docker image ls demo-fyc-api
docker history demo-fyc-api:1.2
```

L'image attend PostgreSQL et une `APP_KEY` fournis par l'environnement. Avec la
base locale du chapitre 1.1 :

```sh
docker run --rm -p 3333:3333 --env-file .env \
  -e HOST=0.0.0.0 -e DB_HOST=host.docker.internal \
  demo-fyc-api:1.2
```

## Observer

- Modifier un contrôleur puis reconstruire : l'étape `pnpm install` reste en cache (`CACHED`).
- Modifier `package.json` : le cache des dépendances est invalidé.
- `docker run --rm demo-fyc-api:1.2 whoami` affiche `node`, pas `root`.
- `docker ps` affiche l'état `healthy` après quelques secondes.
