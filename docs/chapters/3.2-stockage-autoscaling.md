# 3.2 — PVC, métriques et autoscaling

Le tag `3.2` ajoute `deploy/kubernetes/cloud/02-hpa.yaml`.

## Persistance

Le Pod PostgreSQL utilise un PVC : les données sont demandées par Kubernetes et le disque est fourni par la `StorageClass`. Dans le cloud, le disque est généralement indépendant du cycle de vie du Pod, mais son type, sa zone, son débit et sa facturation restent propres au fournisseur.

```sh
kubectl get pvc,pv -n demo-fyc
kubectl describe pvc demo-fyc-db -n demo-fyc
```

## Deux niveaux d'échelle

- **HPA :** augmente ou réduit le nombre de Pods API selon une métrique, ici le CPU moyen ;
- **Node Autoscaler :** ajoute ou retire des nœuds quand les Pods ne peuvent plus être planifiés.

Le HPA ne fonctionne pas sans Metrics Server et des demandes de ressources réalistes. Une valeur `60 %` est un paramètre d'atelier, pas une garantie de performance. Pour mesurer l'effet, générer une charge contrôlée et relever la latence, le nombre de Pods et la capacité du node pool.
