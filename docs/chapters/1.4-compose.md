# 1.4 — Docker Compose : API et PostgreSQL

Le tag `1.4` ajoute `compose.yaml`. Il décrit la stack locale complète sans changer le code de l'API.

## Ce que montre l'atelier

- le service `api` joint PostgreSQL avec le nom DNS `db`, pas avec `localhost` ;
- `depends_on` attend le healthcheck PostgreSQL avant de lancer la migration ;
- le volume nommé `postgres_data` survit à la suppression du conteneur ;
- `/ready` devient une sonde utile pour vérifier que l'API peut réellement joindre sa base.

## Démarrage

Créer une clé locale si nécessaire, puis lancer la stack :

```sh
cp .env.example .env
node ace generate:key
docker compose up --build -d
docker compose ps
curl -i http://localhost:3333/ready
curl -i http://localhost:3333/api/tweets
```

Le fichier `.env` reste local et n'est jamais copié dans l'image. Pour arrêter les conteneurs sans supprimer les données :

```sh
docker compose down
docker compose up -d
```

Pour supprimer aussi le volume de données de démonstration :

```sh
docker compose down -v
```

Cette dernière commande est destructive pour les données locales. Compose orchestre une seule machine ; la haute disponibilité multi-nœuds commence au module 2.
