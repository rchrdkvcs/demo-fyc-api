# 1.2 — Machines virtuelles et conteneurs

Le fil rouge n'est pas encore modifié par ce chapitre : on prépare le vocabulaire qui permettra de comprendre le Dockerfile.

## À retenir

- Une **machine virtuelle** embarque un système d'exploitation invité et son noyau ; l'isolation est forte, mais l'empreinte et le démarrage sont plus lourds.
- Un **conteneur** isole des processus avec les namespaces et les cgroups du noyau hôte ; il démarre vite et partage le noyau de l'hôte.
- Un conteneur n'est pas une machine virtuelle miniature. Une mauvaise configuration (`privileged`, montage du socket Docker, secrets dans l'image) peut réduire fortement l'isolation.

## Observation proposée

Avant de passer à Docker, comparer les ressources demandées par une VM et par un conteneur sur la machine de travail. Le but n'est pas de retenir une taille universelle, mais de relier le choix d'isolation au contexte : multi-tenant strict, développement local, charge prévisible ou besoin de démarrage rapide.
