# 2.1 — Publier l'image

## Ce que ce checkpoint ajoute

`.github/workflows/publish-image.yml` : à chaque tag `module.chapitre` poussé
(`2.1`, `3.2`…), GitHub Actions construit l'image et la publie sur GHCR avec
deux tags : le nom du tag Git et `sha-<commit>`. L'authentification utilise le
`GITHUB_TOKEN` du workflow, aucun secret à créer.

## Lancer

Publication manuelle, pour comprendre ce que fait la CI :

```sh
export IMAGE=ghcr.io/<compte>/demo-fyc-api:2.1
docker build -t "$IMAGE" .
echo "$GITHUB_PAT" | docker login ghcr.io -u <compte> --password-stdin
docker push "$IMAGE"
```

Publication automatique :

```sh
git tag -a 2.1 -m "Publier l'image"
git push origin 2.1
```

## Observer

- Onglet **Actions** du dépôt : le job `publish` construit puis pousse l'image.
- Onglet **Packages** : l'image `demo-fyc-api` et ses tags. La rendre publique
  pour pouvoir la tirer sans authentification depuis le VPS ou le cluster.
- Depuis n'importe quelle machine : `docker pull ghcr.io/rchrdkvcs/demo-fyc-api:2.1`.

Un tag d'image doit désigner un contenu fixe : ne jamais republier un tag
existant avec un autre code. `latest` n'est volontairement pas publié.
