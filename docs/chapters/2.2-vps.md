# 2.2 — Déployer sur un VPS

## Ce que ce checkpoint ajoute

- `deploy/vps/compose.yaml` : l'image `ghcr.io/rchrdkvcs/demo-fyc-api:${API_TAG:-2.1}`
  et PostgreSQL avec volume, `restart: unless-stopped`, API liée à `127.0.0.1:3333` uniquement ;
- `deploy/vps/.env.example` : variables à renseigner sur le serveur ;
- `deploy/vps/nginx/demo-fyc-api.conf.example` : reverse proxy vers l'API ;
- `deploy/vps/README.md` : procédure complète (Docker, Compose, Nginx, Certbot).

Le serveur ne construit rien : il tire l'image publiée au chapitre 2.1.

## Lancer

Suivre [`deploy/vps/README.md`](../../deploy/vps/README.md). En résumé :

```sh
sudo docker compose up -d
sudo certbot --nginx -d api.mon-domaine.fr
curl -i https://api.mon-domaine.fr/ready
```

## Observer (TP2)

- `sudo ss -ltnp | grep 3333` : l'API n'écoute que sur `127.0.0.1`.
- Simuler un crash : `sudo kill -9 $(sudo docker inspect -f '{{.State.Pid}}' $(sudo docker compose ps -q api))`,
  puis `sudo docker compose ps` : Docker relance le conteneur.
- `sudo reboot` puis `curl` : la stack revient seule grâce à `restart: unless-stopped`.
- Noter la durée de chaque coupure : ce relevé sert au bilan du chapitre 2.3.
