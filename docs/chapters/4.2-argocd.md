# 4.2 — Déployer avec Argo CD

## Ce que ce checkpoint ajoute

- `gitops/argocd/application.yaml` : une Application `demo-fyc` qui suit `main`,
  dossier `deploy/k8s`, avec synchronisation automatique, `prune`, `selfHeal`
  et `CreateNamespace=true` ;
- `gitops/README.md` : installation d'Argo CD sur k3d, accès à l'interface, test de dérive ;
- annotations Argo CD sur le Job de migration : il est recréé à chaque
  synchronisation, ce qui contourne l'immuabilité d'un Job.

À partir d'ici, on n'exécute plus `kubectl apply -f deploy/k8s/` : c'est
Argo CD, dans le cluster, qui tire l'état depuis Git (modèle pull).

## Lancer

Suivre [`gitops/README.md`](../../gitops/README.md). En résumé :

```sh
kubectl create namespace argocd
kubectl apply -n argocd --server-side --force-conflicts \
  -f https://raw.githubusercontent.com/argoproj/argo-cd/stable/manifests/install.yaml
kubectl apply -f gitops/argocd/application.yaml
kubectl port-forward svc/argocd-server -n argocd 8443:443
```

## Observer (TP4)

- Interface Argo CD : l'arbre des ressources (Deployment → ReplicaSet → Pods).
- **Sync** : l'Application est `Synced` / `Healthy` ; l'onglet *History* montre le commit déployé.
- **Dérive** : `kubectl scale deployment/demo-fyc-db -n demo-fyc --replicas=0`.
  L'Application passe `OutOfSync`, puis `selfHeal` rétablit `replicas: 1`.
- **Changement par Git** : modifier `LOG_LEVEL` dans `02-config.yaml` sur un
  fork, pousser, cliquer **Refresh** : la ConfigMap est mise à jour sans `kubectl`.
