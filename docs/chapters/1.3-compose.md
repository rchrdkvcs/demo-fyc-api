# 1.3 — Lancer la stack avec Compose

## Ce que ce checkpoint ajoute

`compose.yaml` décrit la stack locale complète :

- service `db` (PostgreSQL 16) avec healthcheck `pg_isready` et volume nommé `postgres_data` ;
- service `api` construit depuis le `Dockerfile`, qui joint la base par le nom de service `db` ;
- `depends_on: condition: service_healthy` : la migration ne démarre qu'une fois la base prête ;
- healthcheck de l'API sur `/ready`.

## Lancer

```sh
cp .env.example .env
node ace generate:key          # ou renseigner APP_KEY à la main
docker compose up --build -d
docker compose ps
curl -i http://localhost:3333/ready
```

## Observer (TP1)

```sh
curl -X POST http://localhost:3333/api/tweets \
  -H 'Content-Type: application/json' -d '{"content":"persistant ?"}'
docker compose down             # supprime les conteneurs, garde le volume
docker compose up -d
curl http://localhost:3333/api/tweets   # le tweet est toujours là
```

- `docker compose logs api` montre la migration puis le démarrage du serveur.
- `docker compose exec api getent hosts db` : le nom `db` est résolu par le réseau Compose.
- `docker compose down -v` supprime aussi le volume : les données sont perdues.

Compose orchestre une seule machine. Le module 2 met cette stack en ligne sur un serveur.
